# odoo-pulse 1.9.1rc1

**This is a release candidate, not a stable release.** It exists so the 1.9.1
fix can be exercised against real Odoo instances before promotion. Install it
deliberately, by exact version — nothing resolves to it by default.

For the full description of what changed in 1.9.1, read
[v1.9.1.md](v1.9.1.md) once the stable release is published. This note covers
only what is specific to the candidate.

## What to expect

1.9.1 is a bug-fix release. `only_closed_stages` / `closed_stage_names`
(`project_dashboard`, `project_subtask_hours`), and `team_workload`'s
`done_stages` / `standup_digest`'s `exclude_stages`, now match tasks by
literal `stage_id.name` only. Previously, on schemas exposing
`project.task.state` or `is_closed`, those internal Kanban fold/closed
markers were preferred over the caller's named stages — a custom stage
folded in the Kanban view but not named `Done`/`Cancelled`/`Delivered` (or
whatever list was passed) could be miscounted as closed, and when
`closed_stage_names` used its default, no name check was applied at all.
Numbers from these tools may shift for projects whose Kanban stage
configuration doesn't align 1:1 with `project.task.state`. Everything else —
tool names, arguments, defaults, schemas — is unchanged.

## Install this candidate

Exact version only. `pip` will not select a prerelease from a range, so pin it:

```bash
pip install "odoo-pulse==1.9.1rc1"
```

```bash
uvx odoo-pulse@1.9.1rc1
```

```bash
docker run -i --rm \
  -e ODOO_URL=https://acme.odoo.com \
  -e ODOO_DB=acme \
  -e ODOO_USERNAME=you@example.com \
  -e ODOO_API_KEY=your-api-key \
  ghcr.io/minhhq-a1/odoo-pulse:1.9.1rc1
```

`1.9.1rc1` is the **only** container tag this candidate publishes. The moving
aliases — `latest`, `1`, and `1.9` — are deliberately not touched, so anyone
tracking them stays on the current stable release and is unaffected by this
candidate.

This candidate is also not published to the MCP Registry. The registry carries
stable releases only.

## What is worth reporting

Anything that differs from 1.9.0 in behaviour, especially:

- `only_closed_stages` / `closed_stage_names` (`project_dashboard`,
  `project_subtask_hours`) reporting different hour totals or task counts
  than 1.9.0 for a project whose Kanban stages don't map cleanly to
  `project.task.state`;
- `team_workload`'s `done_stages` or `standup_digest`'s `exclude_stages`
  moving a task between open and closed compared to 1.9.0;
- anything specific to Odoo 18 versus Odoo 19.

Open an issue at
https://github.com/minhhq-a1/odoo-pulse/issues and state the exact version
(`1.9.1rc1`), your Odoo version, and the tool call involved.

## Going back

The candidate is additive — 1.9.0 is untouched and remains the stable release:

```bash
pip install "odoo-pulse==1.9.0"
```

```bash
docker pull ghcr.io/minhhq-a1/odoo-pulse:1.9.0
```

The MCP surface is identical in both versions, so downgrading needs no client
configuration change.

## Promotion

This candidate soaks for at least 48 uninterrupted hours. If a blocker is
found, it is fixed in a new candidate rather than by re-publishing this one —
release tags and published artifacts are never moved or recreated. If the
soak completes clean, the same code is promoted to 1.9.1 unchanged.
