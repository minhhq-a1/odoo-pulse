# odoo-pulse 1.9.0rc1

**This is a release candidate, not a stable release.** It exists so the 1.9.0
changes can be exercised against real Odoo instances before promotion. Install
it deliberately, by exact version — nothing resolves to it by default.

For the full description of what changed in 1.9.0, read
[v1.9.0.md](v1.9.0.md). This note covers only what is specific to the
candidate.

## What to expect

1.9.0 is a structural release: the package was reorganized into explicit layers
and the report logic was consolidated. The MCP surface is unchanged — 88 tools
with all groups, 31 default tools, one `odoo://{model}/{id}` resource, and every
frozen fingerprint byte-identical to 1.8.2.

So the interesting question for this candidate is not "did the tools change"
but "does it still start, connect, and report correctly in a real deployment".

## Install this candidate

Exact version only. `pip` will not select a prerelease from a range, so pin it:

```bash
pip install "odoo-pulse==1.9.0rc1"
```

```bash
uvx odoo-pulse@1.9.0rc1
```

```bash
docker run -i --rm \
  -e ODOO_URL=https://acme.odoo.com \
  -e ODOO_DB=acme \
  -e ODOO_USERNAME=you@example.com \
  -e ODOO_API_KEY=your-api-key \
  ghcr.io/minhhq-a1/odoo-pulse:1.9.0rc1
```

`1.9.0rc1` is the **only** container tag this candidate publishes. The moving
aliases — `latest`, `1`, and `1.9` — are deliberately not touched, so anyone
tracking them stays on the current stable release and is unaffected by this
candidate.

This candidate is also not published to the MCP Registry. The registry carries
stable releases only.

## What is worth reporting

Anything that differs from 1.8.2 in behaviour, especially:

- the server failing to start, or `odoo-pulse` not being importable;
- a tool that returns an error where 1.8.2 returned data;
- a report whose numbers moved in a way the
  [project finance consistency correction](project-finance-consistency.md) does
  not explain;
- anything specific to Odoo 18 versus Odoo 19.

Open an issue at
https://github.com/minhhq-a1/odoo-pulse/issues and state the exact version
(`1.9.0rc1`), your Odoo version, and the tool call involved.

## Going back

The candidate is additive — 1.8.2 is untouched and remains the stable release:

```bash
pip install "odoo-pulse==1.8.2"
```

```bash
docker pull ghcr.io/minhhq-a1/odoo-pulse:1.8.2
```

The MCP surface is identical in both versions, so downgrading needs no client
configuration change.

## Promotion

This candidate soaks for at least 48 uninterrupted hours. If a blocker is found,
it is fixed in a new candidate rather than by re-publishing this one — release
tags and published artifacts are never moved or recreated. If the soak completes
clean, the same code is promoted to 1.9.0 unchanged.
